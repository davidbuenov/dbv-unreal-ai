## [0.2.0] - 2026-10-27

### Added

- **Photorealistic world generation with World Labs Marble (REQ-18, S27):** full integration with World Labs Marble API (`/marble/v1/worlds:generate`, `/operations/{id}`, `/worlds/{id}`). Allows generating photorealistic worlds from text or reference images (models `marble-1.1` and `marble-1.0-draft`), upfront credit cost estimation, live polling progress, and automatic download of `.spz` Gaussian splats, `.glb` physical collider meshes, and semantic scale/ground metadata into the library. Tools `generate_world` and `export_world_mesh` are exposed in both the integrated assistant and the MCP server, complete with balance queries (`generation_worldlabs_balance`) and a dedicated tab in the Generate view.
- **One-click assistant turn undo (REQ-40, S26):** footer in assistant responses with the «↩️ Undo this turn» button to roll back all modifications performed in Unreal Engine during that turn in a single step. Implemented in the Unreal plugin via `get_undo_count()` and `undo_turn(count, expected_current)` executed via `register_slate_post_tick_callback` to bypass active transaction locks. Includes safety checks and warnings if the editor's undo buffer was modified externally, plus interactive prompts to optionally delete assets created during the turn.
- **Multiple Unreal Engine instances support (REQ-07, S24):** detection and management of multiple Unreal Editor instances running concurrently on adjacent ports (8000, 8001...). Project readiness checks dynamically propose free ports, and connections verify project identity via `get_project_info` to prevent cross-project misrouting. The connection status pill provides a seamless dropdown switcher across all online projects.
- **Interactive character rig attachment for animations (REQ-16, REQ-31):** the 3D animation preview now includes a character rig selector ("3D Character: [ Rust rig | Pumuki rig | Pirata S18 (rig) | 🦴 Skeleton only ]"). When previewing meshless animation clips, Three.js loads the selected character rig and binds the clip's animation tracks to its skeleton in real time, allowing any character in the library to perform the animation with full skin and textures.
- **Native C++ 3D Gaussian Splatting component and Unreal placement (REQ-41, REQ-42, S28b):** implementation of `UDbvGaussianSplatComponent` and `ADbvGaussianSplatActor` (MIT licensed, `DBVUnrealAICpp` module) featuring native `.spz` and `.ply` parsing, camera-facing anisotropic billboard rendering, and depth sorting. Wired into "Send to Unreal" (`sendToUnreal`) to automatically spawn the Gaussian Splat actor and its aligned collision mesh in the level.
- **3D preview quality and thumbnail usability (REQ-31, REQ-42):** clicking on the thumbnail of any card in the library now directly opens the 3D preview (matching the "View in 3D" button). The Three.js viewer now features 3-point studio lighting (key, fill, rim, ambient), smooth vertex normals calculation, and double-sided rendering with a matte neutral clay finish (`#a0aec0`) for untextured collision meshes. World Labs scenarios include an explanatory notice clarifying the mesh is for physics and a toggle button to switch between the 3D mesh and the photorealistic render.
- **Real-time import progress and deduplication (REQ-42):** live progress indicator ("Importing 1/7: …") and button disabling to prevent multiple clicks during batch imports of files and World Labs manifests. Backend automatic deduplication by `world_id` and source path, cleaning up existing duplicate folders on library listing.
- **World Labs scenario import (REQ-42):** support for importing World Labs generation JSON manifests (Marble v1.1, single files or full folders like Wordsmith's). Securely downloads the `.spz` splat, the `.glb` collision mesh (`colliderMeshUrl`), and `.webp` thumbnail, registering the entry with its `metric_scale_factor` and `ground_plane_offset` metadata.
- **Own splats (experimental, spike P-10):** `src-tauri/src/splats` reads a 3D Gaussian Splatting `.ply` (World Labs) and writes a preview mesh (one quad per gaussian); `scripts/spikes` creates in the editor the material that turns it to the camera with a gaussian falloff. Tested with a real world of 1.89 M gaussians (300,000 in the preview). Not in the interface yet.
- **The AI sees the viewport (REQ-13):** `unreal_capture_viewport` gives vision models a capture of the editor (shrunk to ≤ 1568 px as JPEG, from ~2 MB to ~350 KB), optionally with a grid in meters and the nearest actors labeled, so they can check their work. The conversation shows it as a thumbnail. Agents receive it as an image through the app MCP server. It is not offered to models without vision.
- **Tasks with a done-check in the editor (REQ-37):** `asset exists`, `actor exists … count >= N` and `level is` are checked in the editor (fixed app code, read-only; the criterion travels as data) before the task is marked. Without an editor it stays pending. A free-text criterion is confirmed by the user. `project_task_update` tool for the assistant and agents. Verified against Unreal 5.8.4.
- **Plan view (REQ-36):** goal, tasks with their done-check and estimated cost, and next step, read from `dbv-unreal-ai/task.md`. Checking, reopening, editing and deleting write right away without overwriting changes made elsewhere. "Plan" asks the AI for a plan that arrives as an editable card; the app computes the cost with its price table and accepting the plan spends nothing. "Do this task" sends it to the conversation. Agents get `project_tasks_list` and `project_tasks_propose`.
- **Project memory in the conversation (REQ-34, REQ-35):** "Turn on project memory" in the Project view, showing both files first. The assistant gets a summary as a context chip (removable) and agents get it in their first message. When something is decided, the AI proposes saving it with an editable "Save in the project memory?" card (at most one per turn, nothing is written without accepting). "Remember" button in the conversation. Agents read and extend it with `project_memory_read` and `project_memory_propose` of the app's MCP server, which now receives `--project`.
- **Project memory (core, REQ-34):** `dbv-unreal-ai/memory.md` and `task.md` next to the `.uproject`, in English. Only those two files are written, without following links, atomically and checking that nobody changed them since they were read (by hand, by `git pull` or from another process). Nothing that looks like a key is ever saved. "Revert preparation" leaves it alone.
- **World Labs API key** in Settings, stored in the system keychain like the Tripo key (one way only), with where to create it (`platform.worldlabs.ai`).
- README: "Download and install" section for Windows, macOS and Linux with the Release installers, how to get past the SmartScreen and Gatekeeper warnings, and the planned channels (Homebrew, Microsoft Store, Uptodown).

### Fixed

- **Library IPC envelope unpacking in animation viewer (REQ-16, REQ-31):** fixed bug where `api.libraryList()` returned the `{ ok: true, value: [...] }` envelope rather than a bare array, which caused a silent exception (`TypeError: all.filter is not a function`) that prevented the character rig selector (`rigPicker`) from appearing in the animation preview modal. The array is now properly unpacked, pre-selecting matching character rigs or allowing any library character rig to be chosen and animated in 3D.
- **Animation viewer and modal null fix (REQ-16, REQ-31):** fixed literal "null" text appearing under titles in modal dialogs when opening models, rigs, and animation clips (caused by `replaceChildren` converting null arguments to text). Automatic detection of `animation` and `rig` kinds when importing GLBs without geometry; real-time skeletal rendering in Three.js via `SkeletonHelper` (without loop failure), automatic thumbnail inheritance from parent character, and informative header note.
- **Automatic thumbnails in library (REQ-31):** imported 3D models without companion images (`thumbnail: null` in `library.json`) now automatically generate and persist their thumbnail (`thumbnail.png`) offscreen using Three.js in the background, updating the card in real-time. In addition, file imports automatically adopt companion images (`.png`, `.jpg`, `.webp`) sharing the same file stem if present in the source folder.
- DBV Unreal AI toolset 0.3.0 (Python variant): `play_animation` with Tripo skeletons and `place_asset` on the floor. "Prepare" updates it; the C++ variant is unchanged (no recompilation needed).
- The Project view went blank when a project was selected (the memory card used `dirName` without importing it). New test that renders the view with a selected project.
- "How to install" in "Connect an AI" did not open the browser: it called `shell.open`, from a plugin the app does not load, and the `window.open` fallback does nothing inside the WebView. It now uses `opener.openUrl`.
- Gemini CLI is launched with `--acp` (the current flag) instead of `--experimental-acp`. The connection assistant and the AI guide no longer recommend it for subscriptions: since June 18, 2026, Google replaced it with Antigravity CLI for free and Google One accounts, and it only keeps working with paid access.
- **Tripo rejected every model generation** ("HTTP 400: model is required"): the API now requires `model`. Text, image and multiview → model send `v3.1-20260211` when the request has none. Found with the real API; v0.1 had only been tested against a simulated Tripo.
- **An agent's job was lost if its session closed** while the task was running, even though Tripo finished and charged it. The window (or the next `--mcp`) now claims the orphaned job once, keeps waiting for its task and saves it to the library.
- **A Tripo animation did not play on its character** even though `play_animation` answered "success": the clip's GLB carries its own copy of the skeleton. If the bones match (case-insensitively, like Unreal), the clip's skeleton is declared compatible; if not, the error says what is missing. The clip is also applied right away and updates in the editor viewport.
- **What is placed in front of the camera stays on the floor**, not floating in mid-air: it is dropped onto whatever is below.

### Verified

- With the real Tripo API (2026-10-26): text → model, image → model (with file upload), rig and one animation. The real cost matched the estimate in all five (105 credits). The rig and its animation reached Unreal 5.8.4 as a Skeletal Mesh and an Animation Sequence.

## [0.1.0] - 2026-10-24

First release: connection to Unreal 5.8 through MCP, project preparation, conversation with a local or cloud AI or agents with permissions, the whole Tripo API with console and cost, a library with 3D viewer and send to Unreal, and the app's own MCP server.

### Added

- Project bootstrap with the dbv-specs-ops v3.1.0 SDD framework: project identity, activation files for AI assistants, MIT license and initial README.
- Desktop app base from dbv-tauri-starter 0.3.0: Tauri v2, three-tier AI subsystem (local, cloud with OS keychain, ACP agents), with the DBV Unreal AI identity (`com.davidbuenov.dbv-unreal-ai`).
- Unreal Engine 5.8 connection (REQ-01..REQ-05): detection of engine installs (even when Epic's launcher list does not name them), `.uproject` projects and running editors; editor MCP client (`Mcp-Session-Id` session, tool search, text `list_toolsets`, double-encoded results), verified live against UE 5.8.2; readiness check and "Prepare" with diff, backup and byte-exact "Revert"; refuses to prepare while the project's editor is open.
- DBV Unreal AI toolset for Unreal (REQ-06, REQ-25, REQ-26): content-only Python project plugin with `run_python` (undo transaction, stdout/stderr/warnings), `validate_python` (finds missing or deprecated APIs without running the code), `describe_python_api` (reference from the running engine), `get_project_info` and `get_scene_summary`; registered, exercised and unregistered live in the editor. C++ variant as a template that delegates to the same Python package (not compiled yet).
- Unreal tools for the assistant (REQ-10, REQ-12, REQ-26): Epic's server meta-tools (`list_toolsets`, `describe_toolset`, `call_tool`) plus own shortcuts; read/modify classification by verb with an allow-list (anything unknown asks); approval card showing the full Python code; Python is validated against the running engine before asking, and missing names go back to the model to fix.
- Tripo v3 and library (REQ-15, REQ-17, RNF-04): text-to-model with mandatory cost confirmation and a per-session credit cap, immediate GLB download (links expire after 5 minutes) and a local library shared across projects. Image-to-model pending verification with a real key.
- Send to Unreal (REQ-19): Interchange import through the DBV toolset `import_model` (Epic's `import_file` forces FBX and rejects GLB) and placement in front of the camera under `DBV/Generated`; verified live with a real Tripo GLB (correct scale, material and texture).
- Own MCP server (REQ-20): `dbv-unreal-ai --mcp [--port n] [--project path]` over stdio, no network port; bridge to the editor MCP (with mandatory Python validation), library, send to Unreal and Tripo generation (requires `confirm_cost: true` and honours the cap); verified live against the editor. The C++ toolset template switches to `snake_case` names to share the contract with the Python variant.
- DBV Unreal AI UI (REQ-08, REQ-14, REQ-24, DESIGN.md): sidebar (Project · Conversation · Generate · Library · Settings), Unreal connection pill, automatic connection to the editor running the MCP server, readiness check explaining each item, "Prepare" with a per-file diff and "Revert", action log exportable to Markdown, cost card with focus on "Cancel", dark theme by default plus light, ES/EN. The AI assistant loads when the Conversation opens, with the Unreal and generation tools and the MCP servers for ACP agents.
- CI and release (ADR-V010-001 D1): verification on every push (Rust, Vitest, Python toolset, linter) and a draft Release with Windows, universal macOS and Linux binaries when a tag is pushed.
- "Copy diagnostics" in Settings (RNF-08): version, system, Unreal installations and open editors, without keys or prompts.
- Evals with a real model against the real editor (`npm run eval:unreal -- --model qwen3:8b --toolset unreal-plugin/DBVUnrealAI/Content/Python`): the same loop and tools as the app, with the ground truth computed by querying the editor. With `qwen3:8b`: 5/5 in three runs and zero modifications without approval.
- When an API is deprecated, the validation and the API reference give the equivalent editor subsystem call (`unreal.get_editor_subsystem(unreal.EditorActorSubsystem).get_all_level_actors()`), and the system prompt explains the Unreal 5.8 subsystem pattern.
- Tagged tests for every v0.1 requirement (REQ-11 with MCP servers in `session/new`, REQ-13, RNF-01, RNF-05 with measured latency, RNF-06, RNF-07, RNF-IA.2).
- Top bar like the other DBV apps: Light/Dark/**Sepia** selector (a full warm palette; there was only light and dark), ES/EN as a segmented selector and a **pin** that keeps the window on top of the others (per window and not persisted: a decision of the moment, not a preference).
- **The whole Tripo API, for the AI and for the agent (REQ-33, REQ-16).** Catalogue of the 18 v3 operations that create a task (`generation/catalog.rs`, read from developers.tripo3d.ai on 2026-10-24), priced with the official table. Tools defined once in Rust (`generation/tools.rs`) and published identically by the own MCP and the built-in assistant: `generate_3d_model` (with `variants` and a required `name`), `image_to_3d_model`, `rig_model` (rig v1.0 with Tripo's 101 presets, or a skeleton with Unreal bone names), `animate_model` (up to 5 animations, names validated before spending), `tripo_run` for any other operation (convert to FBX, retopology, texture, segmentation, multiview, images…), `tripo_operations` and `tripo_balance`. Every result is a library asset linked to its source (model → rig → animation).
- **Console and progress of every job (REQ-27).** The exact request sent to Tripo (without the key), the task, every status change and the result; in Generate and in the conversation, also for what an agent starts from its `--mcp` subprocess. The MCP no longer blocks: it launches in the background, waits up to 45 s and returns the status; `generation_jobs` keeps waiting.
- **Variants (REQ-29):** 1–4 models from the same request; the cost card shows the total and the cap is checked against it.
- **Meaningful names (REQ-28):** the tool requires a short name; in Generate, "Suggest" asks the connected AI (or a heuristic without AI).
- **Tripo balance** (`GET /v3/account/balance`) in Generate and for the AI.
- **Library (REQ-30, backend):** configurable location (shared with `--mcp`), import `.glb/.gltf/.fbx/.obj/.usdz` models with their buffers, `.mtl` and textures, or images, or folders of another library without duplicates; rename.
- Unreal Dev Community Málaga logo as the app icon (Windows, macOS, Linux), in the top bar, in About and in the READMEs; transparent outer background.
- **Library (REQ-30, REQ-16, interface):** each asset says what it is (model, rig, animation, image) and where it comes from, and offers the next step with its cost card: "Rig…" a model, "Animate…" a rig (picker by groups —dances, emotions, sports…—, at most 5) and "Make 3D…" an image. "Import…" your own models and images and "Import library…" from another folder; rename; each asset's folder. In Settings, the library folder (shareable with other apps, copying what was there) and the Tripo balance.
- **3D viewer (REQ-31):** Three.js 0.180 bundled in the app (no network). "View in 3D" in the Library (orbit, zoom, spin and the list of animations if the GLB has clips); in the conversation, the freshly generated model and the one the AI is about to bring into Unreal spin before you approve. If an asset had no thumbnail (imported ones), the viewer makes it.
- **Reference attachments (REQ-32):** 📎 in the conversation to attach images (PNG, JPG, WebP) and documents from any folder. A vision model gets the image; one without vision gets its name and path, and the user is told; an agent gets it as an image if it supports it (ACP). The AI always knows the local path, so it can use it with `image_to_3d_model`. In Generate, "Reference image" runs image → model (the image is uploaded to Tripo with `/v3/files`). Attachments last for one turn.
- **Characters in Unreal (REQ-16, REQ-19), toolset 0.2.0:** a Tripo rig or animation is imported as a Skeletal Mesh with its Skeleton and Animation Sequences; when placed, the actor plays the first animation in the viewport (new `play_animation` tool, in the Python and C++ variants). With an older toolset it is imported anyway and the user is told to prepare the project again; preparation already detects that the installed one is 0.1.0.
- **Documentation in two languages, in separate files** (project rule in `project.config.md`): README, CHANGELOG, AI guide and the notes of each version (`dbv-specs-ops/releases/vX.Y.Z.md` and `vX.Y.Z.en.md`, generated with `scripts/release/notes.py` from both CHANGELOGs). The GitHub Release carries the notes in English and Spanish and attaches both files.

### Fixed

- The connection pill went back to "No editor" when the AI assistant loaded: `applyTranslations()` rewrote its text because it carried `data-i18n` (caught by the headless Edge UI bench).
- The preparation diff did not mark lines skipped at the start and the end with "…".
- With an 8B model, counting actors with Python ran out of its 12 steps: the deprecated-API warning ("use the subsystem") did not say which one and the model could not find the alternative (caught by the eval; from 14 editor calls down to 4).
- [Critical] "Prepare" left the project half-changed and impossible to revert if a write failed (the backup manifest was written last). It is now all-or-nothing: manifest before writing and automatic rollback on failure.
- [Critical] A Tripo job that failed instantly (bad key) left the UI "Queued…" until the timeout: the event arrived before anyone listened. The listener is now registered before starting and keeps what arrives.
- [Important] The session credit cap was consumed even when Tripo rejected the request without creating a task; now only jobs that create a task count (new "Sent to Tripo…" stage), also in the own MCP server.
- [Important] Model downloads only accept HTTPS (they used to accept `http://127.0.0.1`, meant for tests).
- [Important] An expired MCP session has its own error type instead of being recognised by its message text.
- [Important] `#![deny(clippy::unwrap_used, clippy::expect_used)]` crate-wide (except startup) and the single-`return` rule applied to the MCP client, Tripo, the generation job, preparation, the own MCP server and the Unreal tools.
- The window stayed black with `npm run tauri dev`: `index.html` started with a UTF-8 BOM (inherited from the starter) and Tauri decides the content type from the first bytes, so the WebView downloaded it instead of rendering it. The installer would have been affected too. BOM removed (also from `main.js`) plus a regression test requiring the file to start with `<!doctype html>`. It was hidden because the Edge benches set the type from the file extension.
- With a subscription agent (Claude Code…) the AI still introduced itself as "a Markdown documents assistant": the Unreal prompt only reached local and cloud models. The agent now gets the Unreal one with the exact tool names of its MCP server (a test cross-checks them against `mcp_server.rs`), without the `purpose` instruction, which belongs to our permission card.
- Text and behaviours of the base document editor were left over: conversation suggestions ("Summarise this document", "Check the spelling"), cloud notice, tools hint, file tool descriptions, `get_outline` (meaningless without an open document) and the empty "Context:" bar. All of it is now Unreal-specific, in Spanish and English.
- The proposal check applied Markdown rules (unclosed code blocks, `$$`, links) to any file: a `.py`, `.ini` or `.cpp` with `a[0](x)` or triple quotes gave false errors. They now only apply to `.md`/`.markdown`.
- `run_python` returns the value of the last expression, like a console. Models write the result that way; the code ran fine but `result: null` came back and they thought it had failed.
- Concrete hints when code fails, instead of similar names from a deprecated class: a missing member is looked up (also approximately) in the editor subsystems (`EditorLevelLibrary.get_current_level` → `LevelEditorSubsystem`); `get_editor_subsystem(unreal.EditorLevelLibrary)` is rejected before running; a runtime `AttributeError` (`world.get_all_actors()`) brings `EditorActorSubsystem.get_all_level_actors()`; the API reference accepts expressions with calls.
- If the model writes Unreal Python in its reply without calling `unreal_run_python`, the app reminds it once (nothing had run and the user saw no approval card).
- The Eval uses the same system prompt as the app (`--prompt full`) and can be compared with the short one (`--prompt domain`).
- **Generate and the Library did not work in the real app:** the ten `generation_*` and `library_*` commands were written but not registered in `invoke_handler`. Saving the Tripo key said "Command generation_set_key not found", the key status never reached "Generate" (it said there was no key) and the Library listed nothing. Every test mocked the backend, so nobody saw it. They are now registered and a test cross-checks every command the interface uses against `invoke_handler`.
- In a conversation with an agent (Claude Code…) the answer appeared at the very top and the steps and permission card below, even though they had arrived first: the user expected the answer after their approvals. If a step or card was already added after the bubble, the following text starts another bubble at the end.
- The session spend lived in the window's memory: what an agent generated through the MCP did not count towards the cap. It is now computed from the job files of both processes, and what Tripo reports as failed (not charged) does not count.
- Two variants finishing at the same time lost a library entry (both read the index and the second overwrote the first). The index now has an in-process and cross-process lock.
- The estimated cost was a fixed 30; it now follows the official price list (text with texture 20, +10 low poly, rig 25, 10 per animation…).
- The E2E bench left the Edge instances it launched alive (`msedge.exe` is a launcher: `kill()` closed nothing). There were up to 453 processes and the bench measured another run's stale page. It now closes the browser through CDP and by profile, and refuses to start if the debugging port is taken. Probably the cause of the "flaky E2E" noted as debt.
- With a user-chosen library folder, thumbnails and models would not have shown: the `asset` protocol only opened the default folder. The chosen folder (and every picked reference image) is now opened at runtime.
- **[Critical, v0.1.x `/code-simplify` review] Uploading arbitrary files to Tripo.** The `input`/`image` fields accept a local path that is uploaded to Tripo; a prompt injection could make the AI upload `~/.ssh/id_rsa` with `rig_check`, which is free and shows no cost card. Only images (png, jpg, webp, ≤ 20 MB) and models (glb, gltf, fbx, obj, stl, ≤ 150 MB) are uploaded now, checked before the file is read.
- **[Important]** The result of an image generation (`text_to_image`, `image_to_image`) was stored as the thumbnail and the asset had no file: "Make 3D…" with that image failed.
- **[Important]** A job id could clash between the window and an agent's `--mcp` if both launched in the same millisecond; it now carries the process id.
- Review nits (3): early `return`s outside guard clauses in `tools::build`, `resolve_source` and `uploadable`.
