## [Unreleased]

### Added
- **Drape for tops and trousers (REQ-98):** the shell no longer copies the anatomy. For each height band it takes the convex hull of the body (bridging the sternum and the spine) and lets it hang: going down, the fabric only moves 0.1 cm closer per cm on a top. It only moves away from the skin, never into it. On Pablo's tank top the median clearance goes from 0.98 to 2.93 cm and the abs no longer show.
- **Tops and trousers built from the character's own body (REQ-98):** `outfit/shell.py`. The Tripo garment is no longer deformed: it is placed on the full body with a single scale and position, decides which skin it covers (armholes, neckline and length come from the garment; the crotch is always covered; the arm stays out if it has no sleeves), and the garment is that skin lifted 1 cm (top) or 0.6 cm (trousers), so the top sits outside at the waist. Colour and metal/roughness are baked from Tripo; the weights are the body's. It is the path used by "Send to Unreal" in the Library and by the pipeline for `Torso` and `Legs` (skirts keep their own path). On `Pablo` with the tank top and running shorts: 0 vertices inside the skin and about 6 s per garment.
- **Outfit evals (REQ-88):** new tasks in `scripts/eval/unreal-eval.mjs` checking that the AI uses the deterministic tool, asks when the target is ambiguous and infers the garment kind. The verification matrix (REQ-90) is still pending.
- **Top welding, two-sided materials, and 4 LODs (REQ-81):** new `weld_mesh_vertices` and `weld_top_dynamic_mesh` functions in `dbv_unreal_ai.outfit.fit` to safely weld mesh borders without collapsing open anatomical boundaries; `apply_two_sided_materials` to enforce `override_two_sided=True` and `two_sided=True` across material instances and base assets eliminating invisible backs; and `setup_garment_lods` to procedurally regenerate 4 LOD levels using `SkeletalMeshEditorSubsystem.regenerate_lod` synchronized with the MetaHuman body.
- **Garment validation (REQ-89):** `dbv_unreal_ai.outfit.validate` module with open-border count, leader pose linkage, a PIE walk test and captures. **Real clearance** (`outfit/clearance.py`): signed distance from every garment vertex to the full body of its build, counting only the skin the actor draws, plus bare skin inside the garment area found by casting rays from the skin. If it cannot be measured, the result is `error` with the reason. **Real captures:** front, side and back rendered on the spot with a temporary `SceneCapture2D`, showing only the character, in `Saved/DBVUnrealAI/outfits/captures/<actor>/`. Cloth skirts and dresses are not measured per vertex yet and come out as `error` until they are.
- **Single tool and deterministic pipeline to dress MetaHumans (REQ-88):** new `dbv_unreal_ai.outfit.pipeline` module unifying the entire dressing workflow into a stateful 5-step pipeline (`prepare_character`, `apply_slot_rules`, `prepare_skin`, `fit_and_equip`, `finalize`) with `dress_metahuman_start`, `dress_metahuman_step`, `dress_metahuman_status` and synchronous runner `dress_metahuman`. Persists state in `Saved/DBVUnrealAI/outfits/<job_id>.json`, enforces the single active job constraint per editor (D65), and rejects execution during active PIE sessions. Uniformly exposed across `editor.py`, `toolset.py` (`@toolset_registry.tool_call`), `cpp_bridge.py`, native Rust MCP server (`unreal_dress_metahuman`), built-in assistant (`unrealTools.js`), and "Send to Unreal" (`sendToUnreal.js`), with explicit instructions in the system prompt (`unrealPrompt`) prohibiting manual re-implementation via `run_python` while the single tool exists.
- **Automatic Chaos Cloth physics for skirts and dresses (REQ-87):** new `dbv_unreal_ai.outfit.cloth` module implementing procedural cloth simulation in Unreal Engine 5.8. Generates low-poly simulation meshes using `GeometryScript_MeshSimplification`, creates and configures `ChaosClothAsset` and `Dataflow` assets without modal dialogs by binding `DataflowInstance.dataflow_asset`, adds `ChaosClothComponent` to the character's Blueprint via `SubobjectDataSubsystem`, and sets up `SetLeaderPoseComponent` to `Body` in `EventBeginPlay` using `BlueprintTools` DSL.
- **Choosing who gets dressed (REQ-83):** the app no longer equips a garment on "the first MetaHuman in the level". The Library asks who to dress (with one it comes preselected, with several you must pick and with none the garment is only imported), the AI calls `unreal_list_metahumans` and asks when there are several, `library_send_to_unreal` and `unreal_equip_metahuman_outfit` take the target (`metahuman`, `actor_label`) and, without one, they neither equip nor place anything: the garment is only imported and the user is told. If the editor cannot equip it, the error comes back as is instead of leaving the garment loose in front of the camera.
- **Garment types and cut (REQ-84):** Generate offers `top`, `pants`, `skirt`, `dress` and `shoes` instead of the slot, plus a female, male or neutral cut. Each type has its own prompt (a dress is a whole garment without a body) and the cut goes into it. The type and cut are saved in the library and, when equipping, a warning is shown if the cut does not suit the chosen body. Old entries and calls with only `garment_slot` keep working and get their type.
- **"Prepare" enables the plugins for dressing (REQ-87):** `GeometryScripting`, `ChaosClothAssetToolset` and `PythonFoundationPackages` (`numpy` and `Pillow`; the first start needs a network connection), only the ones the project's engine ships, as "Editor only" when the app adds them, with their check and explanation in the diagnosis.

- **Debugging a runtime failure (REQ-97, first step of the black box):** new *Diagnose a runtime failure* recipe and rules in the AI prompt: when a failure happens during play, measure before changing code; a memory note or a comment is a hypothesis, not a fact; say what was measured and what was not; and never record with per-frame callbacks in `unreal_run_python` (on 2026-11-08 one flooded the log with tens of thousands of lines). If the model writes one in its reply, the app reminds it.

### Fixed
- **Sending the same Tripo model to Unreal again imported nothing:** its textures and materials clashed with the first import ("the import produced no assets"). It now retries in a new subfolder.
- **Assertion crash in `INPAINT_WEIGHTS` (`Map.h.inl:651`) and garment distortion (REQ-81):** fixed handling of sparse vertex identifiers (*tombstones*) produced by `weld_mesh_edges` in `GeometryScript`. `GeometryScript_MeshRepair.compact_mesh` is now strictly enforced after edge welding and repair passes, guaranteeing dense `0..N-1` vertex index arrays in `_deform_by_envelopes` and preventing untransformed vertices from remaining anchored at ground level ($Z \in [-50, 0]$), which caused vertical curtain mesh stretching and the null pointer assertion crash in Epic's `TransferBoneWeights.cpp` solver. Added skeleton pre-copy (`copy_bones_from_mesh`) and fallback weight transfer.
- **Validation accepted badly fitted clothes (REQ-89, REJECTED-13):** clearance was estimated by comparing bounding boxes and, on failure, returned a fixed 1.2/2.0 cm; skirts with a trimmed body were reported "without penetration" without measuring; and captures used a path relative to the engine and the asynchronous viewport camera, so they returned paths to files that did not exist. Measured on 2026-11-10: `Pablo_Deportista`'s tank top had 27.8 % of its vertices inside the skin (up to 8.7 cm) and the shorts left 10.2 % of the area bare at the crotch. They now return `error`, and Pablo's factory clothing returns `ok`.
- **Shorts classification and anatomical fitting (REQ-81, REQ-84):** `_is_skirt_shape` now recognizes short/pants keywords (`short`, `pantalon`, `correr`), preventing athletic shorts from being misclassified as a conical skirt with planar waist cuts. Shorts are now procedurally fitted between waist and mid-thigh ($Z \in [75, 103]$) with clean waist overlap with the top.
- DBVUnrealAI plugin: the project would not open after installing it, because it declared a dependency on `GLTFImporter`, which does not exist in UE 5.8.
- MetaHuman clothing (REQ-81): the gap between head and shoulders no longer appears when replacing the stock shirt (`NeckHideScale`, which shrank the neck through the material).
- MetaHuman skirts (REQ-81): straight hem, no open patches, and a tight fit at the hips with a straight drop, without skin poking through the fabric at rest.
- Torso garments (REQ-81): the fit no longer clips the real waist width, which made skin show through.

## [0.4.1] - 2026-11-07

Version v0.4.1: live ElevenLabs balance visibility and session balance caching; advanced local audio synthesis controls with game presets, acoustic negative prompt, and continuous parameters; Claude Code adapter resilience on Windows; and DBV Unreal AI plugins isolation for standalone game packaging (Android / Meta Quest / VR).

### Added

- **ElevenLabs balance visibility and local unlimited credits (REQ-77):** subscription and remaining characters lookup (`character_count`, `character_limit`) via official ElevenLabs API (`/v1/user/subscription`) with dynamic header display in Generate view (supporting the 10,000 free monthly characters and handling missing `user_read` permission gracefully), and a "Local balance: ∞ credits" badge when connected to the local audio microservice.
- **Session balance caching optimization (REQ-77):** in-memory retention of queried quotas for Tripo, World Labs, and ElevenLabs avoiding repetitive network requests when switching tabs, with reactive invalidation and refresh upon completing any generation.
- **Full synthesis parameters panel and presets for local audio (REQ-76):**
  - **1-Click Game Presets:** quick chips (`🔫 Laser Blaster`, `🚪 Hydraulic Door`, `⚡ Thunder & Lightning`, `🕹️ Retro 8-bit`, `⚔️ Sword & Metal`) that configure prompt, negative prompt, duration, diffusion steps, and CFG scale in one click.
  - **Negative prompt with instant acoustic filters:** text field with 1-click chips to eliminate music and vocals (`🚫 No music or vocals`), noise and distortion (`🔇 No noise or distortion`), and dry mode (`🏜️ Dry / For Unreal`) that strips reverb so Unreal Engine's spatial audio engine handles 3D reverb and attenuation.
  - **Synchronized synthesis sliders:** continuous sliders + number inputs for duration (0.5..30s), diffusion steps (`steps`: 10..100), CFG guidance scale (`cfg_scale`: 1.0..15.0), and deterministic seed selector (`seed`) with randomizer button.
  - **Library traceability:** persistence of `negative_prompt`, `steps`, `cfg_scale`, and `seed` inside `LibraryEntry.parameters`.
  - **Contextual adaptation:** intelligent visibility toggling that only displays the local synthesis panel when the active provider is Local (`dbv-audio-service`).

### Fixed

- **DBV Unreal AI plugins isolation for standalone game packaging (Android / Meta Quest / VR):** `DBVUnrealAICpp.uplugin` now explicitly declares its C++ modules as `"Type": "Editor"` with `"TargetAllowList": ["Editor"]`, and `prepare.rs` (`enable_plugins`) automatically confines both `DBVUnrealAI` and `DBVUnrealAICpp` to Editor in `.uproject`. This prevents UnrealBuildTool (UBT) packaging compilation errors in standalone game builds (such as Android/Meta Quest) where Editor-only dependencies like `UnrealEd` or `ToolsetRegistry` do not exist.
- **Local audio microservice status detection (REQ-77):** fixed IPC response parsing in `generateView.js` and `settingsView.js` by checking `st?.value?.ready` instead of wrapper `st?.ready`, eliminating false positive "Local service unavailable (port 8765)" alerts when `dbv-audio-service` is online.
- **Claude Code connection resilience on Windows:** the official ACP adapter (`@agentclientprotocol/claude-agent-acp`) invoked via `npx` failed on Windows with an internal error (`Claude native binary not found for win32-x64`) when Anthropic package updates lacked pre-bundled optional binaries in the npx cache; the app now automatically injects the `CLAUDE_CODE_EXECUTABLE` environment variable pointing to the system's `claude.exe` binary, and surfaces the detailed error message instead of a generic "Internal error".

## [0.4.0] - 2026-11-04

Version v0.4.0: sound effects (SFX) generation and search with local microservice (Stable Audio Open 1.0), ElevenLabs, and interactive Freesound catalog with audio preview and selective addition; native Unreal Engine audio import (`USoundWave` / `SoundCue`) with MCP tool; real-time vision with "📷 Capture Viewport" for multimodal models; configurable Copyright authorship preserving immutable DBV attribution; and resilient Unreal Engine MCP port auto-detection.

### Added

- **Sound effects (SFX) and audio generation & search (REQ-71):** new "Sounds" tab in *Generate* with support for three providers: open-weights local microservice `dbv-audio-service` (`http://127.0.0.1:8765`, running Stable Audio Open 1.0 with zero cloud cost), ElevenLabs Text-to-SFX via official API (`/v1/sound-generation`), and Freesound (interactive catalog search with matching results, integrated HTML5 audio preview, and selective library addition). Generated or downloaded audio is stored in the library (`kind: "sound"`) with an integrated player.
- **Audio asset import into Unreal Engine ("Send to Unreal" for Audio, REQ-72):** direct import of `.wav` files into `/Game/DBV/Audio/` as `USoundWave` (or looping `SoundCue`) assets, and MCP tool `unreal_import_sound` allowing AI agents to bind audio to actor components or 3D world events.
- **Real-time multimodal vision ("Capture Viewport" for AI, REQ-73):** new "📷 Capture Viewport" button in the chat box taking an instant snapshot of the editor via `CaptureViewport`, attaching it as a thumbnail and forwarding it to vision-capable models and agents to analyze the scene.
- **Configurable Copyright authorship with immutable DBV Unreal AI attribution (REQ-74):** enables setting the project's copyright holder in Project Settings, injecting their attribution into new AI-generated files while preserving the underlying attribution to `DBV Unreal AI` and `Built with dbv-specs-ops`.
- **Editor MCP port auto-detection and resilience (REQ-75):** automatically probes ports `8000..8005` if the configured port fails or returns 404, syncing directly with the active MCP port without requiring manual `.ini` adjustments.
- **Expanded Help Center and contextual direct access:** new help tabs for Tripo 3D, World Labs, and Audio & SFX (in Spanish, English, and Chinese) accessible directly via contextual buttons from each section in *Generate* (Text/Image, World, Sounds) and *Settings* (Tripo, World Labs, Audio, and Convai).

## [0.3.1] - 2026-11-03

Version v0.3.1: each conversation with an agent has its own session, its real model and its token counter; images can be pasted (`Ctrl+V`) and dropped into the conversation; the AI also edits the `.md` files at the root and under `docs/**`; every file carries the standard DBV header; and World Labs worlds left half-done are resumed when the app is reopened.

### Added

- **Paste images from the clipboard (`Ctrl+V`), drag and drop, and thumbnail preview in the conversation (REQ-68):** pasting a screenshot or image (`PNG`, `JPG`, `WebP`) into the conversation text box or dropping files onto the panel saves it to disk (`ai_save_clipboard_image`, ≤ 10 MB) and attaches it with both its `base64` data (for vision-capable models and agents) and its real file path on disk (so Tripo or World Labs tools can use it). Attached image chips now display a visual thumbnail.
- **Standard DBV header banner across all own and AI-generated files (REQ-69):** all repository and C++ plugin files carry the standard 6-line header banner (`DBV Unreal AI`, copyright by David Bueno Vallejo and David Bueno Carmona, MIT License and `dbv-specs-ops`), and the Unreal domain prompt instructs the AI and agents to include that same header in every new file they create (`Source/**`, `Content/Python/**`, `docs/**/*.md` and root `*.md`).
- **Resuming orphaned World Labs jobs (REQ-70):** if the app or an agent's `--mcp` closes while a World Labs world generation (`generate_world` or `export_world_mesh`) is running, polling resumes with the World Labs API key and downloads the completed world (`.spz` + `.glb`) into the library, just like Tripo jobs. If there is no World Labs key yet, the job is left "running" and resumes as soon as you add one.

### Changed

- **The AI can also change the `.md` files at the project root and under `docs/**` (REQ-22):** besides `Source/**`, `Content/Python/**` and `Config/*.ini`, the conversation and agents accept changes to `README.md`, `CHANGELOG.md`, any other `*.md` at the root of the Unreal project and `*.md` files under `docs/**`, with the same reviewable diff. `.md` files in other subfolders are still refused, and the AI knows the new rule beforehand.

### Fixed

- **ACP session isolation per conversation, real default model resolution and per-conversation token counter (REQ-67):** (1) creating, switching or deleting a conversation stops the active ACP session and opens a fresh `session/new` so a new conversation never inherits prior context or burns tokens from previous conversations; (2) `ensureSession` preserves `images: true` across all turns of the ACP session, not only the first one; (3) generic model identifiers (`"claude"`, `"default"`, empty) explicitly resolve to the concrete default model shown in the UI (`claude-sonnet-5-5`, etc.) in both `ANTHROPIC_MODEL` and `session/set_config_option`, preventing silent fallback to `opus` from `~/.claude/settings.json`; (4) the bottom token counter tracks only the active conversation's input/output tokens and resets on new conversations; (5) `files.rs` skips `Plugins/` when scanning documents.
- **[Critical, `/code-simplify` review] Dragging and dropping files onto the conversation did not work on Windows (REQ-68):** Tauri's native drag and drop (`dragDropEnabled`, on by default) kept the files and the panel's HTML5 `drop` never fired. The window now disables it, and the app discards files dropped outside the panel so the WebView does not navigate to them.
- **[Important, `/code-simplify` review]** A binary file dropped onto the conversation (a `.gif`, an `.fbx`, a `.uasset`) was attached as an unreadable "text document". It is now refused with a warning, as the 📎 button already did.
- **[Important, `/code-simplify` review]** `resume_orphans(context)` is removed: only the tests used it, and it handed the Tripo key to World Labs too. `resume_orphans(context, keys)` remains, with each service's own key (`service_keys`), the name REQ-70 uses.

### Known issues

- **[Important] REQ-69:** the domain prompt asks the AI to put a header with the app authors' copyright and the MIT License on new files in the **user's** project. It meets the specification, but in an app distributed to third parties (Microsoft Store) it is worth deciding whether that header should carry the user's own name and licence.

## [0.3.0] - 2026-11-01

Version v0.3.0: the AI changes the project's code (only in `Source/`, `Content/Python/` and `Config/*.ini`) and the app compiles the C++ with Live Coding or UBT; guided recipes with a final check in the editor; offline Unreal guides; Simplified Chinese; own GPU Gaussian Splatting with view-dependent colour; World Labs worlds placed at their real scale and also generated from an agent; Convai and level zones; "Improve with AI" in Generate; and fewer approvals and much less context with agents.

### Added

- **Fewer approvals with agents (REQ-12):** when an agent (Claude Code, Antigravity, Codex…) asks permission for a **read-only query** of the app server (listing or describing toolsets, summarising the scene, capturing the viewport, the library, checking a recipe, searching the guides…), the app grants it on its own and notes it in the conversation with "✓ Read-only, no approval needed". `unreal_call_tool` also goes through on its own if the Unreal tool only reads (`get_…`, `list_…`), with the same rule as the integrated assistant. Anything that modifies, runs Python or spends credits still asks, and so do the agent's own tools. The `--mcp` tools are also published with the standard `readOnlyHint` annotation.
- **Simplified Chinese (REQ-64):** a third language for the whole interface, the conversation, the help (F1, with the Convai tutorial) and the recipes, with the **中文** button in the selector. It is picked automatically when the system is in Chinese; anything missing in Chinese is shown in English, and the AI answers in Chinese. The AI translated it: a native speaker should review it. The common AI guide and the backend error messages stay in Spanish or English.
- **Offline Unreal guides (REQ-25):** the AI can search the Unreal Engine 5.8 guides with `search_unreal_guides` (in the conversation and in `--mcp`), offline: it returns up to 5 short fragments with the URL of their section. It reads a local copy in the MCPCLiente format that you choose in the new **Settings → Knowledge** tab, which explains how to get it with [dbv-mcp-server](https://github.com/davidbuenov/dbv-mcp-server) and links to its repository; the app does not download or bundle any Epic documentation. The search uses BM25 scoring, splits CamelCase names (`NavMeshBoundsVolume` → "nav mesh bounds volume") and takes under 0.1 s over the 5,294 sections after the first one.
- **Guided recipes (REQ-23):** the "📋 Recipes" button in the conversation offers four tasks the AI does step by step, asking approval for each change: *Test level* (floor, light, sky, `PlayerStart` and NavMesh), *Tripo character with animations*, *Walk through a World Labs world* and *MetaHuman that talks with Convai*. At the end, `recipe_check` checks in the editor what is done and what is missing. They also open from "See the guided recipes", next to the suggestions of an empty conversation. Agents get them as `recipes_list` and `recipe_check` in `--mcp` and as editor Agent Skills (`ListSkills`). The Python toolset moves to 0.3.2: "Prepare" will offer to update it.
- **"Improve with AI" in Generate (REQ-66):** next to the Tripo and World Labs text prompt, a button turns a short idea into a detailed description suited to each service (one object for Tripo, a place for World Labs), in English. It replaces the field text without generating anything, with "Undo". It is always a one-off request outside the conversation: with a model, a call without tools; with an agent, a separate ACP session without tools, and the app does not jump to the conversation. With no AI, the button is disabled.
- **Logos in Generate (REQ-65):** each Generate tab shows the Tripo or World Labs logo.
- **Compile after an AI code change (REQ-22):** when you accept a proposal that touches C++, the app compiles. If only `.cpp` files change, it uses Live Coding with the editor open. If headers, `*.Build.cs` or `*.Target.cs` change, a card asks you to close the editor, compiles with UnrealBuildTool and offers to reopen it. Errors go back to the AI on their own at most twice in a row; after that you decide. Agents using `--mcp` get `compile_project_code`. "Prepare" enables `LiveCodingToolset` in C++ projects.
- **The AI only changes the code it should (REQ-22):** in the conversation, change proposals and agent writes are only accepted in the project's `Source/**` (C++ and `*.Build.cs`), `Content/Python/**` and `Config/*.ini`. Never `.uasset`/`.umap`, nothing outside the project or under `Plugins/`, least of all the plugins the app installs. Anything forbidden is refused with the reason, and the AI knows the rule beforehand. "Undo" can still restore any file to how it was.
- **Logos in Settings (REQ-60):** the Tripo, World Labs and Convai tabs show the service logo next to the title, on a dark badge that looks the same in the dark, light and sepia themes.
- **World Labs worlds placed for real (REQ-18):** when a world is sent to Unreal, the splat goes at its metric scale with the ground at Z = 0, the `.glb` collision is aligned with it (scale (m, m, −m): the glTF import mirrors it in Z), uses its complex collision as simple so a character walks on the dunes and not on the mesh box, and a `PlayerStart` left under the terrain is lifted onto it. Before, the collision was left "in front of the camera", unaligned.
- **View-dependent colour on splats (REQ-62):** degree 1–3 spherical harmonics of `.ply` and `.spz` files are evaluated on the GPU with the view direction, so highlights change as you move, as in the original viewer. Each cloud has a video memory budget (`dbv.Splat.VRAMBudgetMB`; 40% of VRAM by default): if it does not fit, the harmonics go first and then only the most visible splats stay, and the report to the AI says so. Only visible splats are drawn: the GPU counts them and the draw is indirect.
- **Own GPU Gaussian Splatting (REQ-61):** the C++ plugin draws splats on the GPU. It uploads them once, projects and sorts them in each view (with the engine radix sort) and composites them after the tonemapper with a depth test: meshes occlude them, and colours come out as captured. They show in the editor, in Play and in the app's captures. The test church (9,975,598 splats, 2.35 GB) runs at about 57 fps on an RTX 4070 Ti. It replaces the CPU renderer, which drew at most 262,144 splats. C++ plugin 0.3.0 with a new module, `DBVUnrealAICppRender`.
- **Several memory entries per proposal (REQ-50):** the AI no longer says it "can only note one reminder per turn". `project_memory_propose` takes up to 8 entries, shown in a single card with a checkbox, editable text and reason for each. Repeated ones come unchecked and the ones that look like a secret are blocked. The "Remember" button asks for everything worth remembering. Through the app's MCP server the valid entries are saved and each one is reported.
- **Tool counter at the foot of each answer (REQ-51):** "Tools: N calls · X KB (~Y tokens, approx.)", also with agents. For these the `--mcp` records it in `tool-usage.jsonl`, with no content. It warns above 200 KB in a turn.
- **`unreal_scene_summary` in the app's MCP server (REQ-51):** the compact scene with filters and a default limit of 100 actors.
- **Convai (REQ-55, REQ-56):** the Project view has a Convai section that checks the plugin (also installed in the engine from Fab), the engine version, the toolsets and the 17 guides in the editor and the sign-in, and warns if the key is in git. The app asks for no key: the plugin signs in by itself. The conversation gets the Convai rules (read its guides, ask for the Character ID, Blueprint components, talk in Play). The approval card of a Convai action and "Undo this turn" warn that Blueprints are saved. New suggestion: "Make this MetaHuman talk with Convai".
- **Level zones (REQ-57):** `level_zones_propose` and `level_zones_list`, in the assistant and in the app's MCP server. The AI proposes named places with a description, you review them in a card and they are created as `TargetPoint`s in `DBV/Zones`, with a `ConvaiObjectComponent` when Convai is installed, so the character knows them and can walk there. The app fixes the code and the zones travel as data. They are undone with the editor (verified live).
- **Duplicate editor access warning (REQ-52):** if the project has a `.mcp.json` (or another agent configuration) pointing at the editor MCP server, the Project view warns about it, with a button to show the file and what to do (delete the entry ending in `/mcp`). The Convai instructions in `CLAUDE.md` do not trigger it: they give no editor access and are useful. The app does not touch those files. The agent preamble and the MCP `instructions` tell it to use only `dbv-unreal-ai`.
- **Local rotating log (RNF-08):** `<data>/logs/dbv-unreal-ai.log` (1 MB × 3) from the window and the `--mcp`: start-up, connections, imports with their final path, sends. Keys are masked before writing. "Copy diagnostics" adds whether the app is packaged, the real folders and the last 50 lines.

- **Convai characters in Settings (REQ-58):** a Convai card, like the Tripo and World Labs ones but with no key, where you register several characters with their name, their Character ID from the Playground and a note. The AI looks them up with `convai_characters` (also through the app's MCP server) and uses the ID by the character's name: "make BP_VictoriaNew be Victoria".
- **Convai tutorial in the F1 help (REQ-59):** what you need (UE 5.8, the plugin signed in, a Playground character and an assembled MetaHuman), the steps and the known issues, with their fixes, seen in the test with a real MetaHuman.
- **Settings with tabs (REQ-60):** Artificial intelligence, Tripo, World Labs, Convai, Library, Agents (MCP) and Diagnostics, instead of one long page.

### Changed

- **Splat readers write the GPU format directly** (D37): the per-point struct holding a `TArray` (10 M allocations for the church) is gone, and degree 1–3 spherical harmonics are read from `.ply` and `.spz` (REQ-62). The `load_gaussian_splat` report adds `sh_degree`. Python toolset 0.3.1.
- **Much less context for agents (REQ-51):** the app's MCP server cuts each result to 12,000 characters, like the built-in assistant, saying how to ask for less. `unreal_describe_toolset` returns one line per tool (Niagara went from 306 KB to 5.5 KB) and with `tool` the schema of a single one. The toolset list is kept in memory and captures are 1024 px by default (`detail: "high"` for 1568). With a fixed script against recorded responses of the real editor, v0.3.0 returns 79% less text than v0.2.4.
- **Library in `Documents/DBV Unreal AI/Library` (REQ-53):** or in `<user folder>/DBV Unreal AI/Library` if OneDrive syncs Documents, so gigabytes of models are not uploaded to the cloud. - **Library (REQ-30, REQ-16, interface):** each asset says what it is (model, rig, animation, image) and where it comes from, and offers the next step with its cost card: "Rig…" a model, "Animate…" a rig (picker by groups —dances, emotions, sports…—, at most 5) and "Make 3D…" an image. "Import…" your own models and images and "Import library…" from another folder; rename; each asset's folder. In Settings, the library folder (shareable with other apps, copying what was there) and the Tripo balance.
- **3D viewer (REQ-31):** Three.js 0.180 bundled in the app (no network). "View in 3D" in the Library (orbit, zoom, spin and the list of animations if the GLB has clips); in the conversation, the freshly generated model and the one the AI is about to bring into Unreal spin before you approve. If an asset had no thumbnail (imported ones), the viewer makes it.
- **Reference attachments (REQ-32):** 📎 in the conversation to attach images (PNG, JPG, WebP) and documents from any folder. A vision model gets the image; one without vision gets its name and path, and the user is told; an agent gets it as an image if it supports it (ACP). The AI always knows the local path, so it can use it with `image_to_3d_model`. In Generate, "Reference image" runs image → model (the image is uploaded to Tripo with `/v3/files`). Attachments last for one turn.
- **Characters in Unreal (REQ-16, REQ-19), toolset 0.2.0:** a Tripo rig or animation is imported as a Skeletal Mesh with its Skeleton and Animation Sequences; when placed, the actor plays the first animation in the viewport (new `play_animation` tool, in the Python and C++ variants). With an older toolset it is imported anyway and the user is told to prepare the project again; preparation already detects that the installed one is 0.1.0.
- **Documentation in two languages, in separate files** (project rule in `project.config.md`): README, CHANGELOG, AI guide and the notes of each version (`dbv-specs-ops/releases/vX.Y.Z.md` and `vX.Y.Z.en.md`, generated with `scripts/release/notes.py` from both CHANGELOGs). The GitHub Release carries the notes in English and Spanish and attaches both files.

### Fixed

- The connection pill went back to "No editor" when the AI assistant loaded: `applyTranslations()` rewrote its text because it carried `data-i18n` (caught by the headless Edge UI bench).
- The preparation diff did not mark lines skipped at the start and the end with "…".
- With an 8B model, counting actors with Python ran out of its 12 steps: the deprecated-API warning ("use the subsystem") did not say which one and the model could not find the alternative (caught by the eval; from 14 editor calls down to 4).
- [Critical] "Prepare" left the project half-changed and impossible to revert if a write failed (the backup manifest was written last). It is now all-or-nothing: manifest before writing and automatic rollback on failure.
- [Critical] A Tripo job that failed instantly (bad key) left the UI "Queued…" until the timeout: the event arrived before anyone listened. The listener is now registered before starting and keeps what arrives.
- [Important] The session credit cap was consumed even when Tripo rejected the request without creating a task; now only jobs that create a task count (new "Sent to Tripo…" stage), also in the own MCP server.
- [Important] Model downloads only accept HTTPS (they used to accept `http://127.0.0.1`, meant for tests).
- [Important] An expired MCP session has its own error type instead of being recognised by its message text.
- [Important] `#![deny(clippy::unwrap_used, clippy::expect_used)]` crate-wide (except startup) and the single-`return` rule applied to the MCP client, Tripo, the generation job, preparation, the own MCP server and the Unreal tools.
- The window stayed black with `npm run tauri dev`: `index.html` started with a UTF-8 BOM (inherited from the starter) and Tauri decides the content type from the first bytes, so the WebView downloaded it instead of rendering it. The installer would have been affected too. BOM removed (also from `main.js`) plus a regression test requiring the file to start with `<!doctype html>`. It was hidden because the Edge benches set the type from the file extension.
- With a subscription agent (Claude Code…) the AI still introduced itself as "a Markdown documents assistant": the Unreal prompt only reached local and cloud models. The agent now gets the Unreal one with the exact tool names of its MCP server (a test cross-checks them against `mcp_server.rs`), without the `purpose` instruction, which belongs to our permission card.
- Text and behaviours of the base document editor were left over: conversation suggestions ("Summarise this document", "Check the spelling"), cloud notice, tools hint, file tool descriptions, `get_outline` (meaningless without an open document) and the empty "Context:" bar. All of it is now Unreal-specific, in Spanish and English.
- The proposal check applied Markdown rules (unclosed code blocks, `$$`, links) to any file: a `.py`, `.ini` or `.cpp` with `a[0](x)` or triple quotes gave false errors. They now only apply to `.md`/`.markdown`.
- `run_python` returns the value of the last expression, like a console. Models write the result that way; the code ran fine but `result: null` came back and they thought it had failed.
- Concrete hints when code fails, instead of similar names from a deprecated class: a missing member is looked up (also approximately) in the editor subsystems (`EditorLevelLibrary.get_current_level` → `LevelEditorSubsystem`); `get_editor_subsystem(unreal.EditorLevelLibrary)` is rejected before running; a runtime `AttributeError` (`world.get_all_actors()`) brings `EditorActorSubsystem.get_all_level_actors()`; the API reference accepts expressions with calls.
- If the model writes Unreal Python in its reply without calling `unreal_run_python`, the app reminds it once (nothing had run and the user saw no approval card).
- The Eval uses the same system prompt as the app (`--prompt full`) and can be compared with the short one (`--prompt domain`).
- **Generate and the Library did not work in the real app:** the ten `generation_*` and `library_*` commands were written but not registered in `invoke_handler`. Saving the Tripo key said "Command generation_set_key not found", the key status never reached "Generate" (it said there was no key) and the Library listed nothing. Every test mocked the backend, so nobody saw it. They are now registered and a test cross-checks every command the interface uses against `invoke_handler`.
- In a conversation with an agent (Claude Code…) the answer appeared at the very top and the steps and permission card below, even though they had arrived first: the user expected the answer after their approvals. If a step or card was already added after the bubble, the following text starts another bubble at the end.
- The session spend lived in the window's memory: what an agent generated through the MCP did not count towards the cap. It is now computed from the job files of both processes, and what Tripo reports as failed (not charged) does not count.
- Two variants finishing at the same time lost a library entry (both read the index and the second overwrote the first). The index now has an in-process and cross-process lock.
- The estimated cost was a fixed 30; it now follows the official price list (text with texture 20, +10 low poly, rig 25, 10 per animation…).
- The E2E bench left the Edge instances it launched alive (`msedge.exe` is a launcher: `kill()` closed nothing). There were up to 453 processes and the bench measured another run's stale page. It now closes the browser through CDP and by profile, and refuses to start if the debugging port is taken. Probably the cause of the "flaky E2E" noted as debt.
- With a user-chosen library folder, thumbnails and models would not have shown: the `asset` protocol only opened the default folder. The chosen folder (and every picked reference image) is now opened at runtime.
- **[Critical, v0.1.x `/code-simplify` review] Uploading arbitrary files to Tripo.** The `input`/`image` fields accept a local path that is uploaded to Tripo; a prompt injection could make the AI upload `~/.ssh/id_rsa` with `rig_check`, which is free and shows no cost card. Only images (png, jpg, webp, ≤ 20 MB) and models (glb, gltf, fbx, obj, stl, ≤ 150 MB) are uploaded now, checked before the file is read.
- **[Important]** The result of an image generation (`text_to_image`, `image_to_image`) was stored as the thumbnail and the asset had no file: "Make 3D…" with that image failed.
- **[Important]** A job id could clash between the window and an agent's `--mcp` if both launched in the same millisecond; it now carries the process id.
- Review nits (3): early `return`s outside guard clauses in `tools::build`, `resolve_source` and `uploadable`.
