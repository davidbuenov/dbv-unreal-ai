# DBV Unreal AI v0.6.1 — Release notes

**[🇪🇸 Español](./v0.6.1.md) · 🇬🇧 English** · 2026-11-15

Version v0.6.1: **Fab on Unreal Engine 5.8.4** from the app. You ask "I want a car" and see each product with its **thumbnail and its fab.com link** before installing it, in the conversation and in the new **Fab view**. Only **free or already owned** products are installed (nothing is bought from the app), and only those **compatible with your editor version**, Quixel Megascans included. What you install stays as a **reference in the Library**. The app is also ready for machines without our tools: it **finds the engine** even when the project says a GUID, lets you **choose its folder**, ships the **C++ plugin already compiled** for 5.8 and the 5.9 Preview (Fab and splats without Visual Studio) and explains every step with a **diagnosis you can copy**.

### Fixed
- **"Copy diagnostics" did not anonymize in two cases (REQ-120, `/code-simplify` review):** if the text had a character whose lowercase changes length, the user folder and name were not removed; and if the anonymized report could not be read back, the original was returned. Now the match is ASCII-only, the name is also removed as-is, and the worst case returns the anonymized text.
- **Fab: a library error is no longer shown as "you do not own it" (REQ-104):** when checking whether a paid product is yours, a 404 from the account (the `ff_agents_api` flag) or any other error is reported as is, instead of `no_owned`.
- **A mature Fab product's details are no longer opened without asking (REQ-105):** the Fab eval with `qwen3:8b` opened one without asking. Now `fab_listing_details` does not return it without `confirm_mature`, and the app asks the person with the approval card even if the model sets it on its own. The rule lives in the code, so it also holds for local models.
- **"There is no Unreal installation {GUID}" with projects of a registered engine (REQ-118, S148):** the app now finds the engine when the project does not say `5.8` but a GUID or a name. That is the case of an engine built from source or registered by hand, read from `HKCU\Software\Epic Games\Unreal Engine\Builds` on Windows or from `Install.ini` on Linux and macOS. Also when it says nothing because it lives inside the engine folder. The registry is only read. If it still cannot find it, the message explains in plain words which engine the project asks for and no longer only points to the Epic Games Launcher. The Project view shows the real engine version instead of the GUID.

### Known (`/code-simplify` review, Important)
- Checking whether a paid product is in your library searches by its title and looks at the first 24 results: with a very common title it could say you do not own it. Free products are not affected.
- If a project already had the C++ plugin source from an earlier preparation and "Prepare" now installs the binaries, the old source stays (preparation does not delete files). Loading without `Source/` was checked, not with an old `Source/` next to it.
- The C++ Fab install functions (`DbvFabInstall.cpp`) have several early `return`s after failures, outside the single-`return` rule. They are left as they are until after the release.

### Added
- **"Fab" view in the sidebar (REQ-106, S144):** search Fab without writing to the AI, with format, "Free only" and sort filters, and a grid of cards with thumbnail and fab.com link. It has the "Catalog" and "My library" tabs, the Fab session and "Load more", never a total. The details show the description, licenses and compatible formats. "Install" asks for confirmation. The rules are the same as in the conversation: only what is compatible with your editor, only free or owned products, and a mature product only opens if you confirm. Search works without the editor.
- **What you install from Fab stays in the Library as a reference (REQ-107, S145):** each successful install creates or updates a Fab entry with its thumbnail, its link and the projects where it was installed, without copying the files. Installing it in another project adds that project to the same entry. From the Library, "Install in this project" asks Fab for it again, with the same rules and after confirming.
- **Plain-language diagnosis and project "Copy diagnostics" (REQ-120, S150):** the Project view shows the steps in order: engine, version, Epic plugins, MCP server auto start, toolset, editor open, MCP server answering and C++ plugin compiled. Each failure carries its fix in one sentence, with nothing to open. "Copy diagnostics" puts those steps on the clipboard together with a report with the app version, the system, whether it comes from the Store, the engines (registered ones too), the project and the end of the log, so the user can send it to you. No keys and no Windows user folder or user name (they become `%USERPROFILE%` and `<user>`). The one in Settings › Diagnostics now leaves them out too.
- **C++ plugin already compiled: Fab and splats without Visual Studio (REQ-121, S151):** the app ships the `DBVUnrealAICpp` plugin compiled for Unreal 5.8 and for the 5.9 Preview (1 MB each). If the project's engine is compatible (same `BuildId` as its editor, like every 5.8.x from the Epic Games Launcher), "Prepare" installs it already compiled and without the source, so it works in a Blueprint-only project and on a machine without Visual Studio. The C++ variant can then be chosen in any project and is preselected. With an engine built from source the code is copied as before. Checked on a Blueprint-only project: the editor loads the plugin and its toolset without compiling.
- **Choose the Unreal folder by hand (REQ-119, S149):** if the app cannot find a project's engine, the Project view says so in plain words and offers "Choose the Unreal folder…". The engine folder or any folder inside it works. It is checked to be Unreal 5.8 or later with the editor, and it is remembered for that project, without touching the `.uproject` or the registry. From then on "Open in Unreal", the diagnosis, "Prepare", compiling and the agents use it. You can go back to automatic detection.
- **Fab on UE 5.8.4, feasibility spike (REQ-101, S138):** the C++ plugin uses the Fab session you already opened in the editor to read your Fab library and the download info, without opening another session. The token stays inside the editor: it is not stored, not written to the logs and not returned in any response. Requests run as jobs (`fab_start`, `fab_status`, `fab_cancel`) so the editor does not freeze while Fab answers.
- **"Prepare" and Fab (REQ-108, S146):** if the project has the `Fab` or `EOSShared` plugins disabled, the diagnosis says so and "Prepare" enables them again. They are not added to projects that leave them alone, since they are enabled by default. On UE 5.9 the same client works, because the Fab API it uses is the same.
- **Fab eval (S147):** `node scripts/eval/fab-eval.mjs -- --model <model>` checks, with an Ollama model and a simulated catalog, that the AI never states a total of results, never installs without approval, never claims a paid listing you do not own was installed, never offers to buy, gives the link of every product it names, asks before opening a mature one, searches by seller with its id and does not retry after an EULA.
- **Quixel Megascans and multi-piece models from Fab (REQ-104):** Megascans, now free on Fab, install in medium quality by default (`quality`: `low`, `mid`, `high` or `raw`) without having to choose between their four zips. If a model arrives in several pieces (an FBX with wheels, body, windows…), a `BP_<Title>` Blueprint assembles them in place, so it can be placed and moved as one object.
- **Fab in the conversation (REQ-105, REQ-117, S142, S143):** the built-in AI and the agents (`--mcp`) get `fab_search`, `fab_listing_details`, `fab_my_library`, `fab_install` and `fab_sign_in`. If you ask "I want a car", a strip of cards appears under the answer with the thumbnail, the seller, whether it is free or already yours, the formats compatible with your editor, the **"View on fab.com"** link and, when possible, **"Install"** (with your approval). The cards are drawn from Fab's data, not from what the AI writes. Agents receive the link and the thumbnail of each product. Installing and signing in ask for permission; searching does not.
- **Install from Fab on UE 5.8.4 (REQ-104, S140, S141):** the C++ plugin installs a Fab product into the open project, but only if it is free or in your library (otherwise `no_owned` with the fab.com link: nothing is bought from the app) and only in a format compatible with your editor (an Unreal pack without `UE_5.8` gives `incompatible_engine`). `glb`, `gltf` and `fbx` files are imported into `/Game/Fab/<Title>/`. Unreal packs are downloaded with BuildPatchServices, as Epic does, into a temporary folder and moved into `Content/` when done. Cancelling halfway leaves nothing in the project. If a product has several files, the list comes back to choose from without downloading anything.
- **Fab catalog search without a session (REQ-102, REQ-117, S139):** the app searches Fab without needing the editor open. Each result comes with a thumbnail (only from `media.fab.com`), the link to its fab.com page, the seller, whether it is free and its rating ("no ratings" instead of 0). Only products that can be installed in your editor's version show up: an Unreal format without `UE_5.8` does not count on 5.8, and `glb`, `gltf` and `fbx` files always do.
