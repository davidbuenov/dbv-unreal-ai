# DBV Unreal AI v0.6.0 — Release notes

**[🇪🇸 Español](./v0.6.0.md) · 🇬🇧 English** · 2026-11-14

Version v0.6.0: **compatible with Unreal Engine 5.8.4 and 5.9** with the same app and the same plugin, and what the 5.9 assistant brings, from the app: **Cursor and OpenCode agents**, **autonomy levels** and **alerts** when the AI is waiting for your approval, the **Unreal Canvas tools**, the **editor MCP instructions** and the **Knowledge Base**. **World Labs worlds are no longer mirrored**, you can choose the **splat renderer** (ours or Epic's GaussianSplat plugin), and the **"os error 17" when connecting an AI in the Microsoft Store version** is fixed.

### Added
- **Unreal Engine 5.9 support alongside 5.8.4 (REQ-109, REQ-110, REQ-112, REQ-116):** the same app and the same plugin work with both engines; where the editor answers differently, the app tries the 5.8 form and, if it does not exist, the 5.9 one.
  - **Version of the connected editor:** the connection reads the editor's real version (`serverInfo.version`). If the project is from another version (you opened it by hand with another engine), it warns that saving converts it with no way back. The connection pill and the AI use the real version, and 5.9 is marked as "Preview".
  - **"Prepare" by engine:** on 5.9 it enables `AllToolsets` (avoiding Epic's known issue of an MCP server with no tools) and writes the MCP settings to the section that engine reads (on 5.9 the module is called `ModelContextProtocol`). The app reads both sections.
  - **Approvals by each tool's mark:** on 5.9 every tool says whether it reads, writes or executes (`accessMode`), and the app uses it: a tool marked as writing asks for permission even if its name looks like a query. On 5.8, with no mark, the usual rule applies.
  - **The AI knows what changes in 5.9:** the prompt tells it where the capture, Play In Editor and the native toolsets (Blueprint, Perf, Console…) are, and asks it to prefer them over Python.
  - **Bounded toolset list:** 5.9 has 139 toolsets and the list took almost 16,000 characters at every AI step; now each one has a short description and it fits under the limit (REQ-51). The same list in the built-in AI and in the agents' MCP server.
  - **5.8.4 × 5.9 compatibility matrix** in `walkthrough.md`, and recorded 5.9 editor responses for the tests.
- **Cursor and OpenCode agents (REQ-115):** they connect like the other subscription agents, with the same commands the UE 5.9 Unreal Assistant uses (`agent acp` —or `cursor-agent acp`— and `opencode acp`). OpenCode also lets you use an agent with local models. Shared by the DBV apps (`src/ai`).
- **Autonomy levels (REQ-115):** a selector in the conversation bar with *Ask for everything*, *Read only*, *Ask before changes* (the usual one, by default), *Automatic* (asks only to run code or touch files) and *Full*. It applies to the built-in AI and to agents. Whatever runs or is refused without a card is noted in the conversation, and spending Tripo or World Labs credits is always confirmed, at any level.
- **Notice when the AI is waiting for your approval (REQ-115):** if the app window is not in front (you are in the editor), its taskbar icon flashes and a short sound plays. It applies to the built-in AI and to agents.

- **Choose what loads splats on UE 5.9 (REQ-114):** in Settings › Library, «Splat renderer». By default, the DBV Unreal AI one, which works on 5.8.4 and 5.9 with nothing to enable and paints the color as it comes in the file. The other option is Epic's `GaussianSplat` plugin, which runs the splat through the engine exposure and looks brighter; it has to be enabled in the project. If it is chosen and the plugin is not enabled, the world is loaded with ours and the app (or the agent) says how to enable it. World Labs `.spz` files are turned 180° so Epic's does not put them upside down. Works for the window and for agents.
- **Unreal Canvas tools for the AI on UE 5.9 (REQ-113):** with Canvas active, the editor publishes about 66 tools outside the toolsets (placing splats and cutouts, 3D annotations, rendering and video) that the AI could not see. Now they show up as one more toolset, `EditorMcp.TopLevelTools`, for the integrated AI and for agents, and go through the usual approvals. Generating images, video or 3D is still done in the Canvas app.
- **Editor MCP instructions and Knowledge Base on UE 5.9 (REQ-115):** what you write in Project Settings › MCP Server › Instructions (yours and the project's) now reaches the integrated AI and agents, like a project CLAUDE.md. And if you enable Epic's `KnowledgeBase` and `KnowledgeBaseToolset` plugins, the AI queries that knowledge base before guessing a project convention; the app memory stays its own and is not copied into it.

### Fixed
- **The «Automatic» level ran Epic's Python, the console and files on UE 5.9 without asking (REQ-115, REQ-12; /code-simplify review, Critical):** it promised to ask before running code or touching files, but only recognised our own Python. Now every tool marked `accessMode: execute`, Epic's `execute_python`, `RunConsoleCommand`, Live Coding and any modifying `FileSystemToolset` tool count as «run», for the integrated AI and for agents.
- **"The system cannot move the file to a different disk drive (os error 17)" when connecting an AI in the Microsoft Store version (REQ-90):** the app saves its files with a temporary file and a rename, and in the Store Windows virtualizes the data folder: renaming between the virtual and the real folder fails with that error (a user hit it when connecting Claude Code). Now, if the rename fails, the file is written directly. It covers connections, conversations, the Library, generation jobs, project memory and Convai characters.
- **Ghost toolsets in the list (REQ-51):** the bullets of some UE 5.8.4 and 5.9 descriptions ("- Graph: …", "- Enum value lookups") showed up as toolsets: on 5.9 they were 22 of the "139" (there are 117). The AI saw names that did not exist and those toolsets' descriptions were cut.
- **The UE 5.9 toolset list was cut with more plugins (REQ-51):** with Canvas and GaussianSplat active there were 154 toolsets and the list went over the cap, so the last ones were lost. Now the descriptions are shortened just enough for it to fit whole.
- **Worlds sent from the window were not placed at their scale (REQ-18):** the Library did not pass the placement code when sending, so a World Labs world arrived without its metric scale, without the ground at Z = 0 and with the collision "in front of the camera". From agents it worked. Now the window does the same.
- **World Labs worlds were mirrored (REQ-18, REQ-61):** our splat renderer placed worlds with the ground right but flipped left to right (the playground swings showed up on the other side). The `.spz` comes in a right-handed axis system and Unreal is left-handed, and a rotation alone could not fix it. Now one axis is negated and the world looks like the World Labs thumbnail. The world collision follows the splat with a uniform scale (before, (m, m, −m)). We found it while comparing against the UE 5.9 `GaussianSplat` plugin.
- **Error when the project's engine is not found (REQ-109):** it now explains that opening it with another version converts it with no way back and that, to try it, a copy should be used.
- **Viewport capture and toolset help in UE 5.9 (REQ-109, REQ-112):** with a 5.9 editor, the "📷 Capture viewport" button failed with "Unknown tool CaptureViewport", because Epic moved it to `SceneCaptureToolset.CaptureEditorViewport` and now sends the image as a separate content block. On top of that, `describe_toolset` (singular) no longer exists in 5.9, so the AI could not read the toolsets' help. The app now uses the 5.8 tool and, if the editor does not have it, the 5.9 one (`describe_toolsets`), and gives the response its usual shape. Nothing changes on 5.8.4. Tested live against `PruebaUnreal59` (5.9) and with recorded responses in `tests/fixtures/unreal-mcp/ue-5.9/`.
- **The "📷 Capture viewport" button did not attach the capture (REQ-73):** since v0.4.0 it called two functions that did not exist, so the image was saved to disk but its thumbnail never appeared in the text box nor reached the model, and the error was lost silently. It is now attached like a pasted image. New integration test that clicks the button and looks for the thumbnail.

### Known (/code-simplify review)
- **Cursor and OpenCode not tested live (REQ-115):** they are launched with the same commands as the 5.9 Unreal Assistant and have tests, but they have not been tried with their CLIs installed.
- **A light diagonal line in some world with our renderer:** seen in a capture of *Fantasy Seaside Golden Sands*; to be reviewed.
- **Fab on UE 5.8.4 (REQ-101):** on 5.9 it works through Epic's toolset; on 5.8.4 it is still pending.
- **[Important] The Cursor CLI is also looked up as `agent`, a generic name (REQ-115):** if another program with that name is on the PATH and `cursor-agent` is not, the app would think Cursor is installed and the agent would not start. `cursor-agent` is looked up first. Still to be tested live with the Cursor CLI installed.
