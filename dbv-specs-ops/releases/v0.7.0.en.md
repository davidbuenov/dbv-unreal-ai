# DBV Unreal AI v0.7.0 — Release notes

**[🇪🇸 Español](./v0.7.0.md) · 🇬🇧 English** · 2026-11-20

Version v0.7.0: **UEFN and Verse**. The app detects UEFN and its projects, connects to its MCP server and gives any AI what it needs to write Verse that compiles: a Verse prompt that puts *Scene Graph* first, the real API of your version taken from the project's digests, and Epic's Verse skill, which is downloaded from GitHub and not bundled. The AI proposes changes to `.verse` files, the app writes them through UEFN itself and compiles with `BuildAll` until there are no errors, tests in a UEFN session, and adds its own recipes and UEFNKit for test copies. Also, "Prepare" once again copies the C++ plugin's source code along with its DLLs.

**Getting started with UEFN:** open your project in UEFN, turn on the MCP server in *Edit → Editor Preferences → Agentic Workflows → Model Context Protocol*, pick the project in the "UEFN projects" section of the Project view and press "Connect to UEFN". To try things safely, first make a test copy from the "UEFN project" card.

### Added
- **UEFN in the Project view (REQ-122):** the app finds UEFN, its real version (the newest of the install, the Launcher and the editor log: the Launcher can lag behind after a patch) and your `.uefnproject` projects, with the one open in the editor first. With UEFN closed, "Open UEFN" starts it through the Epic Games Launcher.
- **Diagnostics and connection (REQ-123):** 7 UEFN-only checks, each with a one-sentence fix, and "Connect to UEFN". The app recognises UEFN by its tools and detects port 8000 being taken even when UEFN says "Running". "Enable Python" asks for confirmation first.
- **AI tools with UEFN (REQ-123):** the AI gets UEFN's own tools and only the app tools that do not need our plugin (memory, Tripo, World Labs, Library). Approvals use the kind UEFN declares for each tool.
- **Epic's Verse skill (REQ-124):** "Install Epic's Verse skill" in the project or in your user folder, with `git` or as a zip, and "Update" when there are new commits. It is Epic Games' work (Magnus Enebakk) and the app does not bundle it.
- **Verse with any model (REQ-125, REQ-126):** its own Verse prompt with the 10 rules behind most errors, `verse_reference` to read the skill and `verse_api_search` to look up real signatures in your version's digests, never making them up.
- **Edit and compile Verse in a loop (REQ-127):** with UEFN open, approved changes are written through UEFN itself and compiled with `BuildAll`. Each error goes back to the AI as `file:line · code · message`, up to 5 attempts and with your approval on each one. It warns when an experimental API is used.
- **UEFN session (REQ-128):** start the session, push changes, start and stop the game, status, Verse output with file and line, and the client log.
- **UEFN recipes (REQ-129):** scoring zone, late-joining players, timer and bringing a `.glb` from the Library, all with *Scene Graph* and their own check.
- **UEFNKit built in (REQ-131):** test copy, Epic samples, export to share and delete (with confirmation). It is downloaded pinned to the reviewed version 2.4.0 and its `sha256` is checked before it runs.
- **Verse evals (REQ-130):** 12 tasks with a simulated UEFN; a task only counts if `BuildAll` returns `[]`.

### Security
- **The app no longer reads the UEFN editor's command line:** it carries your Epic access code.
- **`verse_reference` only reads inside the skill** and **UEFNKit rejects values that look like PowerShell parameters** (`/code-simplify` review).

### Fixed
- **"Prepare" always copies the C++ plugin's source code (REQ-121):** with the Microsoft Store install (DLLs matching the engine), the project was left without the `DBVUnrealAICpp` plugin's `Source/` and it had to be copied from the repository. It now goes along with the DLLs.
- The Fortnite install no longer shows up as a "UE 6.0" engine.
- The UEFN session no longer stays "busy" forever after a failure.

### Known
- The proposal card does not say "Apply and compile Verse", although compiling does happen when applying.
- The Verse attempt limit and the skill have no control in Settings yet.
- `verse_api_search` uses the digests on disk: they can lag behind if UEFN has not reopened the project after a patch.
