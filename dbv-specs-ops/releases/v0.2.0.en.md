# DBV Unreal AI v0.2.0 — Release notes

**[🇪🇸 Español](./v0.2.0.md) · 🇬🇧 English** · 2026-10-27

Version v0.2.0: photorealistic world generation with World Labs Marble (`.spz` Gaussian splats and `.glb` collision meshes), one-click AI turn undo in Unreal Engine, multi-instance Unreal Engine editor support, interactive character rig attachment for 3D animation preview, native C++ 3D Gaussian Splatting component, persistent project memory, and interactive project planning.

### Added

- **Photorealistic world generation with World Labs Marble (REQ-18, S27):** full integration with World Labs Marble API (`/marble/v1/worlds:generate`, `/operations/{id}`, `/worlds/{id}`). Allows generating photorealistic worlds from text or reference images (models `marble-1.1` and `marble-1.0-draft`), upfront credit cost estimation, live polling progress, and automatic download of `.spz` Gaussian splats, `.glb` physical collider meshes, and semantic scale/ground metadata into the library. Tools `generate_world` and `export_world_mesh` are exposed in both the integrated assistant and the MCP server, complete with balance queries (`generation_worldlabs_balance`) and a dedicated tab in the Generate view.
- **One-click assistant turn undo (REQ-40, S26):** footer in assistant responses with the «↩️ Undo this turn» button to roll back all modifications performed in Unreal Engine during that turn in a single step. Implemented in the Unreal plugin via `get_undo_count()` and `undo_turn(count, expected_current)` executed via `register_slate_post_tick_callback` to bypass active transaction locks. Includes safety checks and warnings if the editor's undo buffer was modified externally, plus interactive prompts to optionally delete assets created during the turn.
- **Multiple Unreal Engine instances support (REQ-07, S24):** detection and management of multiple Unreal Editor instances running concurrently on adjacent ports (8000, 8001...). Project readiness checks dynamically propose free ports, and connections verify project identity via `get_project_info` to prevent cross-project misrouting. The connection status pill provides a seamless dropdown switcher across all online projects.
- **Interactive character rig attachment for animations (REQ-16, REQ-31):** the 3D animation preview now includes a character rig selector ("3D Character: [ Rust rig | Pumuki rig | Pirata S18 (rig) | 🦴 Skeleton only ]"). When previewing meshless animation clips, Three.js loads the selected character rig and binds the clip's animation tracks to its skeleton in real time, allowing any character in the library to perform the animation with full skin and textures.
- **Native C++ 3D Gaussian Splatting component and Unreal placement (REQ-41, REQ-42, S28b):** implementation of `UDbvGaussianSplatComponent` and `ADbvGaussianSplatActor` (MIT licensed, `DBVUnrealAICpp` module) featuring native `.spz` and `.ply` parsing, camera-facing anisotropic billboard rendering, and depth sorting. Wired into "Send to Unreal" (`sendToUnreal`) to automatically spawn the Gaussian Splat actor and its aligned collision mesh in the level.
- **3D preview quality and thumbnail usability (REQ-31, REQ-42):** clicking on the thumbnail of any card in the library now directly opens the 3D preview (matching the "View in 3D" button). The Three.js viewer now features 3-point studio lighting (key, fill, rim, ambient), smooth vertex normals calculation, and double-sided rendering with a matte neutral clay finish (`#a0aec0`) for untextured collision meshes. World Labs scenarios include an explanatory notice clarifying the mesh is for physics and a toggle button to switch between the 3D mesh and the photorealistic render.
- **Real-time import progress and deduplication (REQ-42):** live progress indicator ("Importing 1/7: …") and button disabling to prevent multiple clicks during batch imports of files and World Labs manifests. Backend automatic deduplication by `world_id` and source path, cleaning up existing duplicate folders on library listing.
- **World Labs scenario import (REQ-42):** support for importing World Labs generation JSON manifests (Marble v1.1, single files or full folders like Wordsmith's). Securely downloads the `.spz` splat, the `.glb` collision mesh (`colliderMeshUrl`), and `.webp` thumbnail, registering the entry with its `metric_scale_factor` and `ground_plane_offset` metadata.
- **Own splats (experimental, spike P-10):** `src-tauri/src/splats` reads a 3D Gaussian Splatting `.ply` (World Labs) and writes a preview mesh (one quad per gaussian); `scripts/spikes` creates in the editor the material that turns it to the camera with a gaussian falloff. Tested with a real world of 1.89 M gaussians (300,000 in the preview). Not in the interface yet.
- **The AI sees the viewport (REQ-13):** `unreal_capture_viewport` gives vision models a capture of the editor (shrunk to ≤ 1568 px as JPEG, from ~2 MB to ~350 KB), optionally with a grid in meters and the nearest actors labeled, so they can check their work. The conversation shows it as a thumbnail. Agents receive it as an image through the app MCP server. It is not offered to models without vision.
- **Tasks with a done-check in the editor (REQ-37):** `asset exists`, `actor exists … count >= N` and `level is` are checked in the editor (fixed app code, read-only; the criterion travels as data) before the task is marked. Without an editor it stays pending. A free-text criterion is confirmed by the user. `project_task_update` tool for the assistant and agents. Verified against Unreal 5.8.4.
- **Plan view (REQ-36):** goal, tasks with their done-check and estimated cost, and next step, read from `dbv-unreal-ai/task.md`. Checking, reopening, editing and deleting write right away without overwriting changes made elsewhere. "Plan" asks the AI for a plan that arrives as an editable card; the app computes the cost with its price table and accepting the plan spends nothing. "Do this task" sends it to the conversation. Agents get `project_tasks_list` and `project_tasks_propose`.
- **Project memory in the conversation (REQ-34, REQ-35):** "Turn on project memory" in the Project view, showing both files first. The assistant gets a summary as a context chip (removable) and agents get it in their first message. When something is decided, the AI proposes saving it with an editable "Save in the project memory?" card (at most one per turn, nothing is written without accepting). "Remember" button in the conversation. Agents read and extend it with `project_memory_read` and `project_memory_propose` of the app's MCP server, which now receives `--project`.
- **Project memory (core, REQ-34):** `dbv-unreal-ai/memory.md` and `task.md` next to the `.uproject`, in English. Only those two files are written, without following links, atomically and checking that nobody changed them since they were read (by hand, by `git pull` or from another process). Nothing that looks like a key is ever saved. "Revert preparation" leaves it alone.
- **World Labs API key** in Settings, stored in the system keychain like the Tripo key (one way only), with where to create it (`platform.worldlabs.ai`).
- README: "Download and install" section for Windows, macOS and Linux with the Release installers, how to get past the SmartScreen and Gatekeeper warnings, and the planned channels (Homebrew, Microsoft Store, Uptodown).

### Fixed

- **Library IPC envelope unpacking in animation viewer (REQ-16, REQ-31):** fixed bug where `api.libraryList()` returned the `{ ok: true, value: [...] }` envelope rather than a bare array, which caused a silent exception (`TypeError: all.filter is not a function`) that prevented the character rig selector (`rigPicker`) from appearing in the animation preview modal. The array is now properly unpacked, pre-selecting matching character rigs or allowing any library character rig to be chosen and animated in 3D.
- **Animation viewer and modal null fix (REQ-16, REQ-31):** fixed literal "null" text appearing under titles in modal dialogs when opening models, rigs, and animation clips (caused by `replaceChildren` converting null arguments to text). Automatic detection of `animation` and `rig` kinds when importing GLBs without geometry; real-time skeletal rendering in Three.js via `SkeletonHelper` (without loop failure), automatic thumbnail inheritance from parent character, and informative header note.
- **Automatic thumbnails in library (REQ-31):** imported 3D models without companion images (`thumbnail: null` in `library.json`) now automatically generate and persist their thumbnail (`thumbnail.png`) offscreen using Three.js in the background, updating the card in real-time. In addition, file imports automatically adopt companion images (`.png`, `.jpg`, `.webp`) sharing the same file stem if present in the source folder.
- DBV Unreal AI toolset 0.3.0 (Python variant): `play_animation` with Tripo skeletons and `place_asset` on the floor. "Prepare" updates it; the C++ variant is unchanged (no recompilation needed).
- The Project view went blank when a project was selected (the memory card used `dirName` without importing it). New test that renders the view with a selected project.
- "How to install" in "Connect an AI" did not open the browser: it called `shell.open`, from a plugin the app does not load, and the `window.open` fallback does nothing inside the WebView. It now uses `opener.openUrl`.
- Gemini CLI is launched with `--acp` (the current flag) instead of `--experimental-acp`. The connection assistant and the AI guide no longer recommend it for subscriptions: since June 18, 2026, Google replaced it with Antigravity CLI for free and Google One accounts, and it only keeps working with paid access.
- **Tripo rejected every model generation** ("HTTP 400: model is required"): the API now requires `model`. Text, image and multiview → model send `v3.1-20260211` when the request has none. Found with the real API; v0.1 had only been tested against a simulated Tripo.
- **An agent's job was lost if its session closed** while the task was running, even though Tripo finished and charged it. The window (or the next `--mcp`) now claims the orphaned job once, keeps waiting for its task and saves it to the library.
- **A Tripo animation did not play on its character** even though `play_animation` answered "success": the clip's GLB carries its own copy of the skeleton. If the bones match (case-insensitively, like Unreal), the clip's skeleton is declared compatible; if not, the error says what is missing. The clip is also applied right away and updates in the editor viewport.
- **What is placed in front of the camera stays on the floor**, not floating in mid-air: it is dropped onto whatever is below.

### Verified

- With the real Tripo API (2026-10-26): text → model, image → model (with file upload), rig and one animation. The real cost matched the estimate in all five (105 credits). The rig and its animation reached Unreal 5.8.4 as a Skeletal Mesh and an Animation Sequence.
