# DBV Unreal AI v0.3.0 — Release notes

**[🇪🇸 Español](./v0.3.0.md) · 🇬🇧 English** · 2026-11-01

Version v0.3.0: the AI changes the project's code (only in `Source/`, `Content/Python/` and `Config/*.ini`) and the app compiles the C++ with Live Coding or UBT; guided recipes with a final check in the editor; offline Unreal guides; Simplified Chinese; own GPU Gaussian Splatting with view-dependent colour; World Labs worlds placed at their real scale and also generated from an agent; Convai and level zones; "Improve with AI" in Generate; and fewer approvals and much less context with agents.

### Added

- **Fewer approvals with agents (REQ-12):** when an agent (Claude Code, Antigravity, Codex…) asks permission for a **read-only query** of the app server (listing or describing toolsets, summarising the scene, capturing the viewport, the library, checking a recipe, searching the guides…), the app grants it on its own and notes it in the conversation with "✓ Read-only, no approval needed". `unreal_call_tool` also goes through on its own if the Unreal tool only reads (`get_…`, `list_…`), with the same rule as the integrated assistant. Anything that modifies, runs Python or spends credits still asks, and so do the agent's own tools. The `--mcp` tools are also published with the standard `readOnlyHint` annotation.
- **Simplified Chinese (REQ-64):** a third language for the whole interface, the conversation, the help (F1, with the Convai tutorial) and the recipes, with the **中文** button in the selector. It is picked automatically when the system is in Chinese; anything missing in Chinese is shown in English, and the AI answers in Chinese. The AI translated it: a native speaker should review it. The common AI guide and the backend error messages stay in Spanish or English.
- **Offline Unreal guides (REQ-25):** the AI can search the Unreal Engine 5.8 guides with `search_unreal_guides` (in the conversation and in `--mcp`), offline: it returns up to 5 short fragments with the URL of their section. It reads a local copy in the MCPCLiente format that you choose in the new **Settings → Knowledge** tab, which explains how to get it with [dbv-mcp-server](https://github.com/davidbuenov/dbv-mcp-server) and links to its repository; the app does not download or bundle any Epic documentation. The search uses BM25 scoring, splits CamelCase names (`NavMeshBoundsVolume` → "nav mesh bounds volume") and takes under 0.1 s over the 5,294 sections after the first one.
- **Guided recipes (REQ-23):** the "📋 Recipes" button in the conversation offers four tasks the AI does step by step, asking approval for each change: *Test level* (floor, light, sky, `PlayerStart` and NavMesh), *Tripo character with animations*, *Walk through a World Labs world* and *MetaHuman that talks with Convai*. At the end, `recipe_check` checks in the editor what is done and what is missing. They also open from "See the guided recipes", next to the suggestions of an empty conversation. Agents get them as `recipes_list` and `recipe_check` in `--mcp` and as editor Agent Skills (`ListSkills`). The Python toolset moves to 0.3.2: "Prepare" will offer to update it.
- **"Improve with AI" in Generate (REQ-66):** next to the Tripo and World Labs text prompt, a button turns a short idea into a detailed description suited to each service (one object for Tripo, a place for World Labs), in English. It replaces the field text without generating anything, with "Undo". It is always a one-off request outside the conversation: with a model, a call without tools; with an agent, a separate ACP session without tools, and the app does not jump to the conversation. With no AI, the button is disabled.
- **Logos in Generate (REQ-65):** each Generate tab shows the Tripo or World Labs logo.
- **Compile after an AI code change (REQ-22):** when you accept a proposal that touches C++, the app compiles. If only `.cpp` files change, it uses Live Coding with the editor open. If headers, `*.Build.cs` or `*.Target.cs` change, a card asks you to close the editor, compiles with UnrealBuildTool and offers to reopen it. Errors go back to the AI on their own at most twice in a row; after that you decide. Agents using `--mcp` get `compile_project_code`. "Prepare" enables `LiveCodingToolset` in C++ projects.
- **The AI only changes the code it should (REQ-22):** in the conversation, change proposals and agent writes are only accepted in the project's `Source/**` (C++ and `*.Build.cs`), `Content/Python/**` and `Config/*.ini`. Never `.uasset`/`.umap`, nothing outside the project or under `Plugins/`, least of all the plugins the app installs. Anything forbidden is refused with the reason, and the AI knows the rule beforehand. "Undo" can still restore any file to how it was.
- **Logos in Settings (REQ-60):** the Tripo, World Labs and Convai tabs show the service logo next to the title, on a dark badge that looks the same in the dark, light and sepia themes.
- **World Labs worlds placed for real (REQ-18):** when a world is sent to Unreal, the splat goes at its metric scale with the ground at Z = 0, the `.glb` collision is aligned with it (scale (m, m, −m): the glTF import mirrors it in Z), uses its complex collision as simple so a character walks on the dunes and not on the mesh box, and a `PlayerStart` left under the terrain is lifted onto it. Before, the collision was left "in front of the camera", unaligned.
- **View-dependent colour on splats (REQ-62):** degree 1–3 spherical harmonics of `.ply` and `.spz` files are evaluated on the GPU with the view direction, so highlights change as you move, as in the original viewer. Each cloud has a video memory budget (`dbv.Splat.VRAMBudgetMB`; 40% of VRAM by default): if it does not fit, the harmonics go first and then only the most visible splats stay, and the report to the AI says so. Only visible splats are drawn: the GPU counts them and the draw is indirect.
- **Own GPU Gaussian Splatting (REQ-61):** the C++ plugin draws splats on the GPU. It uploads them once, projects and sorts them in each view (with the engine radix sort) and composites them after the tonemapper with a depth test: meshes occlude them, and colours come out as captured. They show in the editor, in Play and in the app's captures. The test church (9,975,598 splats, 2.35 GB) runs at about 57 fps on an RTX 4070 Ti. It replaces the CPU renderer, which drew at most 262,144 splats. C++ plugin 0.3.0 with a new module, `DBVUnrealAICppRender`.
- **Several memory entries per proposal (REQ-50):** the AI no longer says it "can only note one reminder per turn". `project_memory_propose` takes up to 8 entries, shown in a single card with a checkbox, editable text and reason for each. Repeated ones come unchecked and the ones that look like a secret are blocked. The "Remember" button asks for everything worth remembering. Through the app's MCP server the valid entries are saved and each one is reported.
- **Tool counter at the foot of each answer (REQ-51):** "Tools: N calls · X KB (~Y tokens, approx.)", also with agents. For these the `--mcp` records it in `tool-usage.jsonl`, with no content. It warns above 200 KB in a turn.
- **`unreal_scene_summary` in the app's MCP server (REQ-51):** the compact scene with filters and a default limit of 100 actors.
- **Convai (REQ-55, REQ-56):** the Project view has a Convai section that checks the plugin (also installed in the engine from Fab), the engine version, the toolsets and the 17 guides in the editor and the sign-in, and warns if the key is in git. The app asks for no key: the plugin signs in by itself. The conversation gets the Convai rules (read its guides, ask for the Character ID, Blueprint components, talk in Play). The approval card of a Convai action and "Undo this turn" warn that Blueprints are saved. New suggestion: "Make this MetaHuman talk with Convai".
- **Level zones (REQ-57):** `level_zones_propose` and `level_zones_list`, in the assistant and in the app's MCP server. The AI proposes named places with a description, you review them in a card and they are created as `TargetPoint`s in `DBV/Zones`, with a `ConvaiObjectComponent` when Convai is installed, so the character knows them and can walk there. The app fixes the code and the zones travel as data. They are undone with the editor (verified live).
- **Duplicate editor access warning (REQ-52):** if the project has a `.mcp.json` (or another agent configuration) pointing at the editor MCP server, the Project view warns about it, with a button to show the file and what to do (delete the entry ending in `/mcp`). The Convai instructions in `CLAUDE.md` do not trigger it: they give no editor access and are useful. The app does not touch those files. The agent preamble and the MCP `instructions` tell it to use only `dbv-unreal-ai`.
- **Local rotating log (RNF-08):** `<data>/logs/dbv-unreal-ai.log` (1 MB × 3) from the window and the `--mcp`: start-up, connections, imports with their final path, sends. Keys are masked before writing. "Copy diagnostics" adds whether the app is packaged, the real folders and the last 50 lines.

- **Convai characters in Settings (REQ-58):** a Convai card, like the Tripo and World Labs ones but with no key, where you register several characters with their name, their Character ID from the Playground and a note. The AI looks them up with `convai_characters` (also through the app's MCP server) and uses the ID by the character's name: "make BP_VictoriaNew be Victoria".
- **Convai tutorial in the F1 help (REQ-59):** what you need (UE 5.8, the plugin signed in, a Playground character and an assembled MetaHuman), the steps and the known issues, with their fixes, seen in the test with a real MetaHuman.
- **Settings with tabs (REQ-60):** Artificial intelligence, Tripo, World Labs, Convai, Library, Agents (MCP) and Diagnostics, instead of one long page.

### Changed

- **Splat readers write the GPU format directly** (D37): the per-point struct holding a `TArray` (10 M allocations for the church) is gone, and degree 1–3 spherical harmonics are read from `.ply` and `.spz` (REQ-62). The `load_gaussian_splat` report adds `sh_degree`. Python toolset 0.3.1.
- **Much less context for agents (REQ-51):** the app's MCP server cuts each result to 12,000 characters, like the built-in assistant, saying how to ask for less. `unreal_describe_toolset` returns one line per tool (Niagara went from 306 KB to 5.5 KB) and with `tool` the schema of a single one. The toolset list is kept in memory and captures are 1024 px by default (`detail: "high"` for 1568). With a fixed script against recorded responses of the real editor, v0.3.0 returns 79% less text than v0.2.4.
- **Library in `Documents/DBV Unreal AI/Library` (REQ-53):** or in `<user folder>/DBV Unreal AI/Library` if OneDrive syncs Documents, so gigabytes of models are not uploaded to the cloud. It is created at start-up, even if empty. If you did not choose another folder, what was in the previous location is copied once, without deleting anything, and Settings says so. "Open folder" creates the folder if it is missing.

### Fixed

- **World Labs did not generate from an agent (REQ-18, RNF-04):** `--mcp` sent World Labs the Tripo key ("No API key found in request") and measured its credits against the Tripo cap (300, while a world costs 1,580), with messages about "Tripo credits". Each service now uses its own key, spending and cap: World Labs has its own in **Settings → World Labs** (2,000 by default), and the cost card and the job console say World Labs. The integrated assistant also asked for the Tripo key for a world. An orphaned World Labs job is no longer resumed with the Tripo client.
- **World Labs still answered "No API key found" (REQ-18):** the World Labs client did not follow the real API: it sent the key in `Wl-Api-Key`/`Authorization: Bearer` (the API uses `WLT-Api-Key`), the text in `prompt` (it is `world_prompt: {type, text_prompt}`), expected `name` instead of `operation_id`, read the balance from `credits` (it is `remaining_credits`) and exported with `type` (it is `asset_type`). It now follows the docs.worldlabs.ai reference. New **`worldlabs_balance`** tool (a query, no permission asked): agents only had `tripo_balance` and called it before generating a world. The World Labs balance shows in **Settings → World Labs** and in Generate → World (if it fails, the reason shows). The integrated assistant did not launch `generate_world` or `export_world_mesh` ("unknown tool"). A world's job card said "Sent to Tripo…" and stayed at "0%": World Labs gives no percentage, so it now shows the elapsed time, that it usually takes about 5 minutes, and an estimated bar.
- **"Prepare" moved the MCP server port for no reason, and the app compiled against the old port (REQ-07, REQ-22):** with the project's own editor open, "Prepare" thought port 8000 was taken by someone else and proposed 8001; after reopening the editor, the app kept talking to 8000 ("could not connect to the editor"). It now keeps the port if the editor itself holds it, Live Coding asks which port the editor is listening on right then, the compile card reconnects on its own when the editor reopens and, if the editor is still starting, offers "Retry".
- **"Unknown tool: get_project_info" on every connection (REQ-07):** when connecting, the app asked for the editor identity without naming the toolset and read the answer wrongly, so the Unreal log filled with errors and it never checked that the editor on the port was the chosen project. It now asks the DBV toolset and does not connect if the editor has another project open.
- **The Unreal editor opened from the app closed by itself, with no crash report:** it was launched inside the app's Job Object, and while developing (`tauri dev` over `cargo run`) Windows killed it every time the app restarted. The app now launches it outside the job (with `CREATE_BREAKAWAY_FROM_JOB` or, if the job does not allow it, through WMI), so it survives the app closing.
- **`.spz` files (World Labs, Scaniverse) were not read correctly by the own actor:** the reader expected another magic (`SPSP`) and another block order, did not decode the colour, version 3 rotations or the harmonics, and did not change axes (SPZ uses RUB and `.ply` RDF). Rewritten after Niantic's format, with tests. What looked right in the v0.2 desert was XGrids.
- **Project memory lost when Unreal restarts itself** (for example after enabling plugins): the editor then starts with the `.uproject` path relative to its `Engine/Binaries/Win64` folder, and the app read it relative to its own, so the agents' MCP could miss the project (above all with the Store app or the project on another drive). It is now resolved against the editor executable (found while testing v0.3.0).
- **Reopening a conversation lost the footer of each answer** ("Undo this turn" and now the tool counter): `addAssistant` read the wrong option. It came from v0.2.0; the `/code-simplify` review found it.
- **The Project view opened and closed a console window on Windows** when checking whether the Convai key is in git: the `git` process was started without `CREATE_NO_WINDOW`, unlike the rest of the app (`/code-simplify` finding).
- **The Microsoft Store version's library could not be seen (REQ-53):** a packaged app writes what it creates in `%APPDATA%` to a private copy that File Explorer, Unreal and the agents do not see. "Open folder" said it did not exist, and a `.ply` imported from a website did not appear in the folder created by hand.
- **Sending a Gaussian Splat from an agent (REQ-54):** the app's MCP `library_send_to_unreal` only accepted `.glb`, `.fbx` and `.obj` ("the asset has no model file"). It now loads the `.spz`/`.ply` with the DBV component and places its collider mesh, with the same file choice as the window (parity test).
